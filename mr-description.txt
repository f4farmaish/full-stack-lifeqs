# Merge Request: Block User Feature & UI Improvements

## Summary
This MR implements a comprehensive block user functionality and several UI enhancements to improve user experience and safety on the Lifeqs platform.

## Features Implemented

### 🚫 Block User Functionality

#### Core Features
- Users can block/unblock other users from their profile page
- Blocked users list accessible at `/profile/{userId}/blocked`
- Real-time updates when blocking/unblocking users

#### Content Filtering
- **Posts & Polls**: Blocked users' content is automatically filtered from:
  - Home feed
  - Questions page
  - All content feeds using `fetchCombinedContent` and `getInfinitePosts`

#### Comments & Replies
- Blocked users' comments show as "Blocked User" with:
  - Generic placeholder avatar
  - Hidden comment content: "[This comment is from a blocked user]"
  - No interaction options (like, reply, reactions)
- Same treatment applied to replies

### 🔗 UI Improvements

#### Clickable Category Titles
- Category titles on posts and polls are now clickable
- Clicking navigates to home page with category filter applied
- Works across all pages (not just home)

#### Clickable User Profiles
- Username and profile picture in comments/replies are clickable
- Blocked users list: Avatar and name are clickable, navigate to profile
- Clicking navigates to user's profile page
- Protected cases: Anonymous and blocked users remain non-clickable in comments

#### Message Blocking
- Users cannot send messages to blocked users
- Users cannot receive messages from users they've blocked
- Conversations list filters out blocked users
- Chat page shows appropriate message when trying to access blocked user's chat
- Different messages for "You blocked this user" vs "This user blocked you"

### 🔧 Technical Improvements

#### Query Optimization
- Added `currentUserId` parameter to content fetching functions
- Implemented server-side filtering for blocked content
- Proper cache invalidation when blocking/unblocking

#### Bug Fixes
- Fixed unblock button missing `unblock: true` parameter
- Fixed profile navigation using correct `userIdString` property
- Added proper TypeScript types and error handling
